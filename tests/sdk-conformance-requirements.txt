# Pinned dependency for tests/sdk_conformance_test.py — the official Model Context
# Protocol Python SDK, used as an INDEPENDENT REFEREE for this server's hand-written
# protocol layer. Its strict parsing is the point: the SDK validates the negotiated
# protocol version, the transport's status codes, and every result it parses, so a
# conformance verdict comes from real client behaviour rather than from this repo's
# reading of the spec.
#
# The pin is DELIBERATE, not incidental — an unpinned SDK would silently change what
# "conformant" means between runs. sdk_conformance_test.py reads the version from this
# file and refuses to run against a different one, so CI and a local run always agree.
#
# Bumping it (see docs/testing.md § Conformance harness):
#   1. edit the version below
#   2. pip install -r tests/sdk-conformance-requirements.txt
#   3. python tests/sdk_conformance_test.py   (against a hub, or the e2e dispatch run)
#   4. read the SDK's release notes for protocol-version changes — a bump that adds
#      2026-07-28 to its SUPPORTED_PROTOCOL_VERSIONS changes which ERA the SDK
#      exercises, which is a real change in what this leg proves
#
# 1.28.1 caps at LATEST_PROTOCOL_VERSION = "2025-11-25" and its
# SUPPORTED_PROTOCOL_VERSIONS is ["2024-11-05","2025-03-26","2025-06-18","2025-11-25"],
# so today this leg exercises the LEGACY era through a real client — which is exactly
# the compatibility surface that matters: every currently deployed MCP client is
# legacy-era, and it is legacy traffic that a presence-based (rather than value-based)
# read of the MCP-Protocol-Version header would break.
#
# Deliberately NOT tracked by Dependabot: this is a test-referee pin whose bump changes
# what the harness asserts, so it stays a human decision (see the ignore list rationale
# in .github/dependabot.yml for the same reasoning applied to the Gradle referees).
mcp==1.28.1
